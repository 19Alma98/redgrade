## Findings

### Major

**M2 — `--family` non rilassa la policy**

In [`cli.py`](../../src/redgrade/cli.py) il filtro famiglie cambia solo gli attacchi caricati; `evaluate_policy` usa ancora `config.policy` intera (`require_families`, `max_asr_by_family`). Un debug `redgrade run --family resource_abuse` fallisce il gate anche se quella famiglia è pulita (copertura / limiti su famiglie non eseguite). Comportamento coperto dal test, ma è una trappola UX non documentata in README/docs.

**M3 — Example consumer action fragile**

[`examples/github-action-gate.yml`](../../examples/github-action-gate.yml): `uv sync` poi `uv pip install redgrade` senza pin di versione; `uv run redgrade` dipende da come l’env del progetto consumatore è fatto. Per 0.1 meglio `pip install redgrade==0.1.0` (o extra esplicito) e un commento su Python ≥3.12 se si usa OpenGrade.

---

### Minor

**m1 — Env var mancanti → stringa vuota**

[`targets.py`](../../src/redgrade/targets.py) `_expand_env`: `${MISSING}` diventa `""` senza warning. Un header `Authorization: Bearer ` vuoto produce 401 come trial error (ok per la safety rule), ma il messaggio è più opaco del necessario.

**m2 — `markdown_exfil` tratta ogni `?` come “data”**

Qualsiasi markdown link/image con query string verso host non allowlistati conta come successo dell’attacco, anche `?v=1`. Coerente coi test; può dare falsi positivi su app reali. Accettabile in alpha se documentato in `writing-attacks.md` con più precisione.

**m3 — Snippet di output nel report Markdown**

I trial riusciti includono fino a 200 caratteri di output (visti secret/PII della demo). Utile in CI summary; manca un avviso docs che i report possono contenere dati sensibili del target.

**m4 — Asimmetria policy family vs severity**

Con zero trial validi, un limite `max_asr_by_family` **fail**; un limite `max_asr_by_severity` viene **saltato**. Difendibile, ma andrebbe una riga in README sotto “How a verdict is reached”.

**m5 — Nessun workflow di publish**

OK per alpha; da annotare come post-0.1 (PyPI trusted publishing / tag-driven release).

**m6 — Gap di test minori**

Copertura buona sulle safety rules (error ≠ pass, skip secrets, flaky, HTTP mock, policy, CLI exit 2, demo, export). Mancano test dedicati a: espansione `${ENV}`, report Markdown structure, `concurrency` + HttpTarget condiviso, install senza extra che non importi `opengrade` accidentalmente al runtime CLI.

- README policy example usa `max_asr: 0.10`; la demo hardened usa `0.15` (spiegato nel commento YAML) — allineato al claim “12% / passed”.

## Fase notes (checklist)

### Packaging / API pubblica

- Version `0.1.0`, classifier Alpha, entry point `redgrade = redgrade.cli:main`: OK.
- Wheel contiene i 5 YAML under `redgrade/packs/`: OK.
- `__all__` in [`__init__.py`](../../src/redgrade/__init__.py) espone runner/policy/models/loader: ragionevole per libreria.
- Extra `opengrade` isolato a livello di import lazy in `make_metric`: OK; rotto solo a livello di risoluzione uv (B1).

### Core pipeline

- Loader valida family/severity/detector/duplicati: OK.
- Render `{CANARY}` poi `{b64:}`/`{rot13:}`: OK e testato.
- Runner: skip senza secrets; errori target → trial error; ASR su valid trials; concurrency preserva ordine id: OK.
- Detectors deterministici: OK.
- Policy “no valid trial ⇒ overall fail”; require_families: OK.
- Report: coverage matrix include famiglie `planned`; disclaimer sicurezza: OK.

### CLI / demo

- Exit codes 0/1/2 rispettati e testati.
- `init` scrive EXAMPLE caricabile.
- Hardened residuali esattamente PI-D-008/009/010 — coerente con README.
- Path `examples.demo_app:...` richiede cwd repo (CI/tests lo impostano): documentato indirettamente dal “Try it” dalla root.

### Docs

- Tabella famiglie README ↔ [`families.py`](../../src/redgrade/families.py) ↔ pack: allineata (26 attacchi, 5 available).
- [`docs/writing-attacks.md`](../writing-attacks.md): sufficiente per un pack custom.
- Limiti onesti (probabilistico, demo simulata, non sostituisce red team): OK.
- Claim OpenGrade “not yet E2E vs live server”: onesto e allineato ai test SDK-only.
